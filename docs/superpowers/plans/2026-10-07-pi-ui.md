# pi-ui Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ridisegnare la chat di Pi (Neon Night) con un pacchetto `pi-ui`: barra di stato, editor, footer, passi compatti, immagini, suggerimenti, permesso nella barra, notifica e pannello.

**Architecture:** Pacchetto Pi locale `pi-ui/` (come `pi-picker`). Ogni parte è una funzione pura testabile (`src/*.ts`) più un piccolo cablaggio in `index.ts` sulle API di estensione di Pi 1.0.4. Nessun tool nuovo e nessun testo nel prompt, salvo i suggerimenti (disattivabili).

**Tech Stack:** TypeScript eseguito da Node 22+ con type stripping, `node:test`, `@earendil-works/pi-coding-agent` / `pi-tui` 1.0.4, `pngjs` + `jpeg-js` (miniature).

**Spec:** `docs/specs/2026-10-07-pi-ui-design.md`

## Global Constraints
- Pi 1.0.4; Node ≥ 22.19; nessuna dipendenza nativa.
- Palette Neon Night (spec): bg `#0c0c0c`, panel `#13121a`, userBg `#1c1326`, text `#dcdfe8`, dim `#858ba0`, faint `#4c5163`, border `#2e3140`, magenta `#ff3fd8`, ciano `#2ee6ff`, giallo `#f5e14a`, ok `#3df2a0`, warn `#f5b942`, err `#ff4d6d`, add `#7cf5bd`, del `#ff8fa8`.
- Testi utente in italiano; codice e commenti in inglese, stile del repo (tab, funzioni pure esportate, commenti brevi sul perché).
- Ogni riga renderizzata ha `visibleWidth(line) === width` (o ≤ width per le righe di contenuto).
- Solo TUI: fuori da `ctx.mode === "tui"` pi-ui non registra niente. `PI_UI=off` disattiva tutto.
- Pannello su `Alt+I` (non `Ctrl+B`: prefisso tmux).
- Costo in token zero, salvo i suggerimenti (`PI_UI_SUGGEST=0` li spegne).

## Review Focus
- Terminale stretto (< 60 colonne): barra, footer, righe dei passi non devono sforare né andare a capo male → test a 40 colonne.
- Turno interrotto con Esc: la barra deve dire FERMO "interrotto", non FATTO → test del reducer con outcome `aborted`.
- Comandi bash filtrati (`npm test | tail`) che nascondono il fallimento: l'esito deve venire anche dal conteggio `fail N` → test di `checkOutcome`.
- Immagine inesistente, corrotta o enorme: nessun crash, voce con solo link e motivo → test di `thumbnailFor`.
- Sessione ripresa (`-c`) con turni vecchi: i passi già finiti non devono girare come spinner → test di `renderTurn` con passi `done`.

```ts
export function fit(left: string, right: string, width: number): string {
	const gap = width - visibleWidth(left) - visibleWidth(right);
	if (right && gap >= 1) return left + " ".repeat(gap) + right;
	return pad(truncateToWidth(left, width), width);
}
```

### Task 2: Stato del turno (reducer puro)

**Files:** Create `pi-ui/src/status.ts`, `pi-ui/test/status.test.ts`

**Interfaces — Produces:**
```ts
export type Mode = "ready" | "working" | "waiting" | "stopped" | "done";
export interface TurnStatus { mode: Mode; activity: string; step: number; startedAt: number; endedAt: number; tokensIn: number; tokensOut: number; lastFailed: boolean; question?: string; answers?: string }
export type StatusEvent =
	| { type: "agent_start"; at: number }
	| { type: "tool_start"; activity: string }
	| { type: "tool_end"; failed: boolean }
	| { type: "usage"; input: number; output: number }
	| { type: "waiting"; question: string; answers: string }
	| { type: "resumed" }
	| { type: "settled"; at: number; outcome: "completed" | "aborted" | "error" };
export function initialStatus(): TurnStatus;
export function nextStatus(status: TurnStatus, event: StatusEvent): TurnStatus;
export function elapsedSeconds(status: TurnStatus, now: number): number;
```
- [ ] Test: start → working "penso…"; tool_start incrementa il passo; usage somma; settled completed → done, aborted → stopped "interrotto", error → stopped; ultimo passo fallito → stopped; un fallimento seguito da un passo riuscito → done; il tempo si ferma a `endedAt`; waiting/resumed.
- [ ] Implementazione; test verdi; commit.
